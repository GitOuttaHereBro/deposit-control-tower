# Project Memory Hub

Project Context, Instructions, and Persistent Memory Management



Hi! I will provide text files containing important information about my project. These files will explain what has already been built, what changes are required, which errors need to be fixed, what tasks need to be completed, what must not be changed, and any other relevant project instructions.



The files may have different names and extensions. Do not assume that every file will have the same name.



1. Read and Understand All Relevant Files

Always read and understand the relevant text files I provide before starting any project-related task.

The files may contain the project's current state, implementation details, completed work, pending tasks, bugs, requested changes, restrictions, and previous decisions.

Consider all relevant files together to understand the complete project context.

Treat the latest applicable instructions as the primary source of truth.

If any important information is missing, unclear, or contradictory, ask me for clarification instead of making assumptions.



2. Create and Maintain a chat.md File



Create a file named chat.md in the project workspace and use it as your central reference for remembering the project's instructions and context.



The chat.md file must contain the following information:



- The purpose and overview of the project.

- What has already been built and implemented.

- What changes have been requested.

- What errors and bugs need to be fixed.

- What tasks are completed, pending, or in progress.

- What must be done next.

- What must not be changed, removed, or implemented.

- Important instructions, restrictions, decisions, and requirements.

- References to other relevant text files and their purposes.

- Any additional information necessary to continue the project without losing important context.



3. Keep chat.md Updated

Whenever I provide new project information, new instructions, or significant updates, incorporate the relevant information into chat.md.

When I provide a new text file, read it, understand its contents, and update chat.md with the relevant information.

Preserve important existing information when updating the file. Do not unnecessarily delete or overwrite previous instructions.

If an old requirement is explicitly changed, update it accordingly while preserving any useful historical context.

Keep the file organized, clear, accurate, and easy to understand.

Do not record assumptions as confirmed facts.

If you cannot create or edit files in the current environment, tell me clearly and provide the complete updated content for chat.md instead.



4. Follow Project Instructions Carefully



Before making any code changes:



- Read chat.md and all relevant project files available to you.

- Understand the existing implementation and the requested task.

- Identify the specific files and functionality that need to be modified.

- Check the restrictions and requirements to ensure that no prohibited changes are made.

- Make only the necessary changes.

- Fix the reported issues without unnecessarily affecting existing working functionality.

- Verify the changes wherever possible and report any remaining problems.



Never rewrite the entire project when only a small change is required. Never remove existing functionality without my permission or an explicit requirement to do so.



5. Handle Different File Names Correctly



The text files I provide may have different names, formats, and purposes. Do not rely on filenames alone to determine their contents.



Read the available files and understand how they relate to one another. If multiple files contain overlapping or conflicting information, carefully identify which instructions are current and ask me when the correct interpretation is uncertain.



Use chat.md as the central index and summary of the project context, while preserving the original files as references whenever appropriate.



6. Maintain Context Across Conversations



The main purpose of chat.md is to help maintain continuity across tasks and conversations.



Before starting work in a new conversation, read the latest available chat.md and the other relevant files to restore the project context.



Do not assume you can automatically access previous conversations, previously uploaded files, or information that is no longer available in the current environment.



Keep chat.md sufficiently detailed so that another session can understand the project's current status, previous decisions, outstanding tasks, and restrictions without requiring me to explain everything again.



7. Provide a Clear Summary After Each Task



After completing a task, briefly explain:



- What you changed or implemented.

- Which errors you fixed.

- Which files you modified.

- What remains incomplete or requires further attention.

- Whether chat.md was updated.



If you could not complete a task or verify a fix, state that clearly rather than claiming success.



Final Rule



Always read the relevant project files, follow my instructions, maintain chat.md as the central project memory file, and update it whenever necessary.



Your goal is to preserve project continuity, avoid losing important information, prevent unnecessary changes, and ensure that every future task follows the project's established requirements and restrictions.
